# Study with Lingxi-claw - Workflow 定义

## 1. 文档目的

本文档定义 Lingxi-claw 四个核心功能模块的具体工作流程：

- 📚 期末突击
- 📝 日常作业辅助
- ❓ 其它问题
- 🤖 Agent 设定

本文档主要用于统一：

1. 前端页面交互流程
2. 后端 Workflow 执行逻辑
3. Router 的路由位置
4. Agent 的介入位置
5. 输入与输出的基本流程

> 产品原则：**用户主动选择大场景，系统在场景内部进行智能路由。**

## 3. 📚 期末突击 Workflow

### 3.1 功能定位

「期末突击」是 Lingxi-claw 面向期末考试场景设计的核心 Workflow。

它不是简单的「上传一份试卷 → AI 总结」，而是针对学生通常拥有大量、格式不统一的历年试题和课程资料这一实际场景，将多个文件统一组织成一个复习资料集合，通过批量解析、题目分类、跨年份考点统计和学习计划生成，为用户建立一套完整的期末复习路径。

核心目标：

> **用户上传一批历年题和课程资料 → 系统自动整理资料 → 构建题目库 → 分析高频考点和题型 → 根据用户剩余复习时间制定计划 → 按优先级刷题 → 根据学习结果动态调整计划。**

---

### 3.2 用户使用场景

用户进入「📚 期末突击」后，可以创建一次新的复习任务。

例如：

```text
课程：高等数学

考试时间：8 月 30 日

每天可学习：4 小时
````

然后用户可以一次性上传一批自己已经积累的学习资料。

例如：

```text
高等数学期末复习资料/
│
├── 2022期末试题.docx
├── 2023期末试题.pdf
├── 2024期末试题.pdf
├── 2025期末试题.docx
├── 老师复习重点.pdf
├── 课程知识点总结.docx
└── 课堂复习PPT.pdf
```

文件可能来自：

* 本地电脑
* 云盘
* 历年课程资料
* 同学整理的试卷
* 教师发布的复习资料

文件格式可能包括：

* Word（`.docx`）
* PDF
* 扫描版 PDF
* 图片
* PPT
* 其他课程文档

系统需要支持**批量上传**，而不是要求用户逐个文件处理。

### 3.3 Dataset：一次复习任务对应一个资料集合

为了统一管理用户上传的一批文件，系统引入 **Dataset（资料集合）** 的概念。

用户创建一次期末复习任务后，对应生成一个 Dataset。

例如：

```text
Dataset
「高等数学期末复习」
│
├── File 1：2022期末试题.docx
├── File 2：2023期末试题.pdf
├── File 3：2024期末试题.pdf
├── File 4：2025期末试题.docx
├── File 5：老师复习重点.pdf
├── File 6：课程知识点总结.docx
└── File 7：课堂复习PPT.pdf
```

Dataset 是整个「期末突击 Workflow」的数据基础。

后续的：

* 文件解析
* 题目提取
* 题型分类
* 知识点识别
* 高频考点统计
* 题目推荐
* 复习计划

都基于这个 Dataset 进行。

### 3.5 Batch File Processor：批量文件处理

由于用户可能一次上传几十个文件，因此不能把整个文件集合直接交给一个 Agent。

系统首先使用 Batch File Processor 对文件进行批量处理。

```text
Dataset
    ↓
Batch File Processor
    ↓
┌────────────┬────────────┬────────────┬────────────┐
│            │            │            │            │
File 1       File 2       File 3       File 4       ...
│            │            │            │
↓            ↓            ↓            ↓
File Router  File Router  File Router  File Router
│            │            │            │
↓            ↓            ↓            ↓
DOCX解析     PDF解析      OCR          DOCX解析
│            │            │            │
└────────────┴────────────┴────────────┴────────────┘
                         ↓
                   统一数据格式
```

每个文件独立处理。

这样可以避免：

* 单个文件处理失败导致整个任务失败
* 不同格式无法统一处理
* 大量文件一次性进入模型造成 Token 浪费
* 后续无法追踪题目来自哪个文件

---

### 3.6 File Router：文件类型路由

File Router 是文件处理阶段的第一层 Router。

它不负责理解题目内容，而是首先判断：

> **这个文件应该使用什么解析方式？**

例如：

```text
文件
 ↓
File Router
 ↓
┌──────────────────────────────────┐
│                                  │
│ DOCX → Word Parser               │
│ PDF  → PDF Parser                │
│ Scan PDF → OCR                   │
│ Image → OCR / Vision             │
│ PPTX → PPT Parser                │
│                                  │
└──────────────────────────────────┘
```

这一阶段优先使用规则和轻量逻辑完成，避免无意义地调用大模型。

---

### 3.7 统一数据格式

不同文件解析完成后，需要转换成统一的数据结构。

例如：

```json
{
  "file_id": "file_001",
  "dataset_id": "dataset_math_001",
  "file_name": "2024高等数学期末试题.pdf",
  "file_type": "pdf",
  "year": 2024,
  "content": "解析后的文本内容",
  "pages": []
}
```

这样后续模块不需要关心：

> 这个内容原来是 Word 还是 PDF？

只需要处理统一的数据。

---

### 3.8 资料清洗与去重

批量上传后，可能存在：

* 同一份试卷重复上传
* 文件内容重复
* OCR 产生乱码
* 页码重复
* 无关封面
* 无关目录
* 教师答案与学生试卷混在一起

因此需要进行基础清洗。

```text
原始文件
    ↓
Text Cleaning
    ↓
去除无关内容
    ↓
Duplicate Detection
    ↓
重复文件 / 重复内容检测
    ↓
Clean Dataset
```

目标不是在这一阶段理解所有知识，而是获得尽可能干净的资料集合。

---

### 3.9 Question Splitter：题目提取

清洗后的资料可能仍然是一整份试卷。

例如：

```text
2024高等数学期末试题

一、选择题
1. ...
2. ...
3. ...

二、填空题
1. ...
2. ...

三、计算题
1. ...
2. ...

四、证明题
1. ...
```

Question Splitter 将资料拆分为独立题目。

```text
整份试卷
    ↓
Question Splitter
    ↓
┌────────┬────────┬────────┬────────┐
│ 题目 1 │ 题目 2 │ 题目 3 │ 题目 4 │
└────────┴────────┴────────┴────────┘
```

每道题保留来源信息。

例如：

```json
{
  "question_id": "q_001",
  "source_file": "2024高等数学期末试题.pdf",
  "year": 2024,
  "question_number": "三-2",
  "content": "题目内容"
}
```

---

### 3.10 Question Router：题目分类路由

题目切分之后，进入 Question Router。

Question Router 的作用是：

> **判断每道题属于什么类型、考查什么知识点，以及后续应该如何使用。**

例如：

```text
题目
 ↓
Question Router
 ↓
识别：
├── 学科
├── 题型
├── 知识点
├── 难度
└── 任务类型
```

例如：

```json
{
  "question_id": "q_001",
  "subject": "高等数学",
  "year": 2024,
  "question_type": "计算题",
  "knowledge_points": [
    "二重积分",
    "换元法"
  ],
  "difficulty": "medium"
}
```

---

### 3.11 Question Bank：题目库

所有题目完成分类后，统一进入 Question Bank。

整体结构：

```text
Dataset
    ↓
Question Bank
    │
    ├── 2022
    │   ├── 选择题
    │   ├── 填空题
    │   ├── 计算题
    │   └── 证明题
    │
    ├── 2023
    │   ├── 选择题
    │   ├── 填空题
    │   ├── 计算题
    │   └── 证明题
    │
    ├── 2024
    │   └── ...
    │
    └── 2025
        └── ...
```

Question Bank 是后续刷题功能的核心数据来源。

### 3.12 Knowledge Point Index：知识点索引

除了题目库，还需要建立知识点索引。

例如：

```text
高等数学
│
├── 极限
│   ├── 极限计算
│   ├── 等价无穷小
│   └── 洛必达法则
│
├── 导数
│   ├── 基本求导
│   ├── 复合函数求导
│   └── 导数应用
│
└── 二重积分
    ├── 直角坐标
    ├── 极坐标
    └── 换元法
```

每个知识点关联对应题目。

```text
知识点：二重积分
        ↓
┌────────┬────────┬────────┐
↓        ↓        ↓
2022题   2023题   2025题
```

这样系统才能统计：

> 哪些知识点在历年试卷中出现最多？

### 3.13 Exam Analysis：历年考试规律分析

当 Question Bank 和 Knowledge Point Index 建立后，系统开始进行跨文件、跨年份分析。

重点分析：

#### 高频知识点

```text
高等数学

★★★★★ 极限
★★★★★ 导数
★★★★☆ 二重积分
★★★★☆ 微分方程
★★★☆☆ 无穷级数
```

#### 高频题型

```text
1. 极限计算题
2. 导数综合题
3. 二重积分计算题
4. 微分方程
5. 证明题
```

#### 跨年份重复考点

例如：

```text
二重积分
2022 ✓
2023 ✓
2024 ✓
2025 ✓

出现：4 / 4 年
```

系统可以将其标记为：

> **高优先级考点**

### 3.14 Study Planner：个性化复习计划

考试重点分析完成后，再结合用户自身情况生成复习计划。

输入包括：

```text
Exam Analysis
        +
用户剩余时间
        +
每天学习时间
        +
用户薄弱知识点
        +
用户学习进度
```

例如：

```json
{
  "exam_date": "2026-08-30",
  "remaining_days": 7,
  "daily_study_hours": 4,
  "weak_topics": [
    "二重积分",
    "微分方程"
  ]
}
```

进入：

```text
Study Planner
```

生成：

```text
Day 1
极限
+ 历年高频题

Day 2
导数
+ 历年计算题

Day 3
积分基础

Day 4
二重积分
+ 薄弱题型

Day 5
综合题

Day 6
模拟考试

Day 7
错题复习
+ 高频考点回顾
```

---

### 3.15 Question Selector：智能刷题

复习计划生成后，系统根据当前学习状态从 Question Bank 中选择题目。

不是简单随机抽题。

Question Selector 综合考虑：

```text
题目优先级 =
考点频率
+
用户薄弱程度
+
题型覆盖情况
+
距离考试时间
+
最近练习情况
```

例如：

```text
用户还有 3 天考试
        ↓
发现「二重积分」属于高频考点
        ↓
用户该知识点错误率较高
        ↓
Question Selector
        ↓
优先推荐二重积分题
```

---

### 3.16 学习反馈与动态调整

用户完成题目后，不只是显示：

```text

```

```text
用户完成题目
        ↓
Answer Checker
        ↓
记录：
├── 是否正确
├── 错误类型
├── 知识点
├── 题型
└── 难度
        ↓
更新 User Learning State
        ↓
重新计算学习优先级
        ↓
调整后续 Question Selector
        ↓
必要时调整 Study Plan
```

例如：

```text
用户连续 3 道二重积分题错误
        ↓
系统判断：
二重积分掌握程度下降
        ↓
提高二重积分优先级
        ↓
增加相关基础题
        ↓
减少已经掌握的知识点
```

### 3.18 期末突击的核心价值

传统 AI 学习工具通常是：

```text
上传一份文件
        ↓
问一个问题
        ↓
得到一个答案
```

Lingxi-claw 的「期末突击」则是：

```text
上传一批资料
        ↓
Dataset
        ↓
批量解析
        ↓
建立题目库
        ↓
跨年份分析
        ↓
发现高频考点
        ↓
结合考试时间
        ↓
生成复习计划
        ↓
智能选题
        ↓
用户练习
        ↓
学习状态更新
        ↓
动态调整计划
```

因此，「期末突击」的核心不是单次问答，而是：

> **把学生散落在电脑和云盘中的历年资料，自动转化成一套可执行的个性化复习系统。**

## 4. 📝 日常作业辅助 Workflow

### 4.1 使用场景

用户需要完成日常作业，但不希望 AI 直接替自己完成。

系统核心原则：

> **AI 是辅导者，不是代做者。**

默认采用：

```text
提示
 ↓
引导
 ↓
用户尝试
 ↓
检查
 ↓
完整解析
```

---

### 4.2 完整 Workflow

```text
用户进入「日常作业辅助」
        ↓
上传作业图片 / 文档
        ↓
[File Router]
        ↓
OCR / 文本解析
        ↓
题目切分
        ↓
[Question Router]
        ↓
识别：
├── 学科
├── 题型
├── 知识点
└── 难度
        ↓
生成题目学习策略
        ↓
提供第一层提示
        ↓
用户自己尝试
        ↓
用户提交答案 / 解题过程
        ↓
[Answer Checker]
        ↓
判断：
├── 正确
├── 部分正确
└── 错误
        ↓
提供针对性反馈
        ↓
用户继续尝试
        ↓
仍无法完成？
        │
        ├── 否
        │     ↓
        │  继续引导
        │
        └── 是
              ↓
        提供完整解题过程
              ↓
        总结通用方法
```

---

### 4.3 用户状态 Router

作业模式中的重要路由不是模型路由，而是：

> **用户现在处于什么学习状态？**

```text
Homework State Router
        ↓
┌────────────────┬────────────────┬────────────────┐
↓                ↓                ↓                ↓
刚看到题目       正在尝试         提交了过程       请求完整答案
↓                ↓                ↓                ↓
提示模式         方法提示         过程检查         完整解析
```

---

### 4.4 分层教学机制

#### Level 1：方向提示

告诉用户应该往哪个方向思考。

```text
例如：

观察题目中的条件，
尝试判断是否可以使用换元法。
```

---

#### Level 2：方法提示

告诉用户可以使用什么方法，但不完成计算。

```text
例如：

可以尝试令：

t = x²

然后将原式转换成关于 t 的表达式。
```

---

#### Level 3：关键步骤

用户仍然不会时，提供关键计算步骤。

```text
例如：

换元之后，下一步需要计算：

∫ f(t) dt
```

---

#### Level 4：完整解析

只有满足以下情况时进入：

* 用户明确请求答案
* 用户多次尝试失败
* 系统判断用户已经理解方法但无法完成计算

输出：

```text
完整解题过程
        +
关键思路
        +
易错点
        +
该题型通用方法
```

## 5. ❓ 其它问题 Workflow

### 5.1 使用场景

适用于没有固定 Workflow 的学习问题。

例如：

```text
什么是贝叶斯公式？

为什么二重积分需要画积分区域？

帮我理解虚拟内存。

帮我制定一个学习方法。

解释这个编程概念。
```

### 5.2 General Agent Workflow

```text
用户输入问题
        ↓
轻量请求分析
        ↓
Request Router
        ↓
判断任务类型
        │
        ├── 简单知识问答
        │      ↓
        │    直接回答
        │
        ├── 用户资料相关
        │      ↓
        │    检索用户资料
        │
        ├── 图片/文档问题
        │      ↓
        │    多模态分析
        │
        ├── 复杂任务
        │      ↓
        │    Task Planning
        │      ↓
        │    多步骤执行
        │
        └── 工具需求
               ↓
            Tool Calling
        ↓
General Agent
        ↓
生成最终回答
```

---

### 5.3 请求复杂度路由

系统不应该所有请求都直接调用最强的大模型。

```text
用户请求
        ↓
Complexity Router
        ↓
┌──────────────┬──────────────┬──────────────┐
↓              ↓              ↓
简单            普通            复杂
↓              ↓              ↓
轻量处理        标准模型         大模型 / Agent
```

例如：

#### 简单请求

```text
什么是概率？
```

可以使用较轻量的处理方式。

#### 普通请求

```text
解释贝叶斯公式，并给我一个例子。
```

使用标准模型。

#### 复杂请求

```text
分析我上传的三份课程资料，
总结它们的关系，
然后帮我制定学习路线。
```

使用：

```text
文件解析
+
资料检索
+
Task Planning
+
Agent
```

## 6. 🤖 Agent 设定 Workflow

### 6.1 功能定位

Agent 设定不是单独的聊天功能。

它负责管理整个 Lingxi-claw 的 AI 行为偏好。

用户设置：

```text
回答风格
教学方式
回答长度
自定义 Prompt
```

↓

转换为：

```text
Agent Profile
```

↓

在后续 Workflow 和 Agent 调用时加载。

---

### 6.2 Agent Profile

建议统一保存为：

```json
{
  "response_style": "standard",
  "response_length": "medium",
  "teaching_mode": "guided",
  "custom_prompt": ""
}
```

---

### 6.3 设置生效流程

```text
用户修改 Agent 设置
        ↓
Settings Validator
        ↓
生成新的 Agent Profile
        ↓
保存用户设置
        ↓
后续请求读取 Profile
        ↓
动态构建 Prompt
        ↓
影响 Workflow / Agent 输出
```

例如用户设置：

```text
回答风格：详细推导
教学方式：先提示再给答案
回答长度：详细
```

作业 Workflow 就应该自动调整：

```text
默认不给完整答案
        ↓
提供更详细的提示
        ↓
用户尝试后检查过程
```

Lingxi-claw 的核心设计不是：

```text

        ↓
主 Workflow / Agent
        ↓
不同阶段调用不同 Router
```

例如：

### 期末突击

```text
Final Sprint Workflow
        ↓
File Router
        ↓
Question Router
        ↓
Study Planner Router
        ↓
Question Selector
```

### 日常作业

```text
Homework Workflow
        ↓
File Router
        ↓
Question Router
        ↓
Homework State Router
        ↓
Answer Checker
```

### 其它问题

```text
General Agent
        ↓
Request Router
        ↓
Complexity Router
        ↓
Model Router / Tool Router
```

## 9. Workflow 设计原则

### 原则 1：用户负责选择大场景

用户明确告诉系统：

> 我现在是在准备期末，还是做作业，还是问其它问题。

减少系统第一步猜测用户意图的成本。

---

### 原则 2：系统负责内部路由

进入场景后，用户不需要知道：

* 用哪个 OCR
* 用哪个文档解析器
* 用哪个模型
* 用哪个 Prompt
* 用哪个 Skill

系统自动完成。

---

### 原则 3：简单任务不用复杂模型

优先采用：

```text
规则 / 轻量分类
        ↓
小模型
        ↓
标准模型
        ↓
复杂 Agent / 大模型
```

只有真正需要时才升级处理能力。

---

### 原则 4：Workflow 优先，Agent 兜底

```text
明确且重复的任务
        ↓
固定 Workflow
```

```text
开放且复杂的任务
        ↓
General Agent
```
